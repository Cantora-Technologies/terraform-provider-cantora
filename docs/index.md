# Cantora Provider

Manage Cantora Agent Configuration through the Management API.

The provider manages stable desired Agent Configuration while Cantora retains immutable Agent Versions, append-only Agent Releases, and Configuration Revision evidence.

Use a Cantora ServicePrincipal with only the grants required for the target Project. Prefer `CANTORA_API_KEY` over an `api_key` argument so the credential does not appear in configuration. Authentication values never enter resource state.

## Example Usage

```terraform
terraform {
  required_version = ">= 1.13.0"

  required_providers {
    cantora = {
      source  = "cantora/cantora"
      version = "~> 0.1"
    }
  }
}

provider "cantora" {
  # Set CANTORA_API_KEY in the environment.
  request_timeout   = "30s"
  source_repository = "acme/agent-configuration"
  source_commit     = var.git_commit
  source_path       = "agents/aria.tf"
  source_workflow   = "terraform-apply"
  source_run        = var.workflow_run
  source_actor      = var.workflow_actor
}

variable "git_commit" {
  type = string
}

variable "workflow_run" {
  type = string
}

variable "workflow_actor" {
  type = string
}
```

## State security

Agent instructions are reviewable customer data and enter saved plans and state. Protect those artifacts with encryption, access control, locking, backup, and retention. Never put credentials, tokens, Connection secret material, or provider refresh material in Agent Configuration.

Provider-level source fields are operation context. They are bound into a reviewed plan only when resource configuration changes; changing provenance alone does not manufacture drift.
